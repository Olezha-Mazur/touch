# Лабораторная работа №2

## Выбранная архитектура
В проекте реализована архитектура **MVVM**. Controller очищен от логики отрисовки и логики перехода. Навигация изолирована в слое `Router`, а бизнес-логика и подготовка данных полностью перенесены во `ViewModel`, которая зависит только от слоя Domain (`Foundation`) и не импортирует `UIKit`. Это делает систему слабосвязанной и легко покрываемой unit-тестами.

## Список модулей и их ответственность
1. **Auth** — Экран старта и входа. Сбор учетных данных, обращение к `AuthServiceProtocol`, управление состояниями (лоадер/ошибка). При успехе `Router` подменяет корневой `UIWindow` на глобальный TabBar.
2. **Feed** — Главная страница (Лента новостей). Запрашивает список постов из Domain-слоя, маппит модели `Post` в UI-модели и отрисовывает `UITableView`. Роутер управляет локальным стеком навигации.
3. **Profile** — Личный профиль (соседняя вкладка меню). Обращается к `ProfileService Protocol` для загрузки имени пользователя. Обрабатывает логику выхода (уничтожение сессии и возврат на экран Auth через `UIWindow`).

## Сценарии по модулям

### Экран Авторизации (Auth Module)
* **Вход:** Нет данных (корневая точка входа).
* **Выход:** Успешный `UserSession`, переключение приложения на TabBar.
* **Состояния (`AuthViewState`):** `initial` (ввод данных), `loading` (спиннер, кнопка неактивна), `error` (сообщение об ошибке).
* **Сценарии:**
  1. Ввод данных пользователем -> Нажатие на кнопку логина.
  2. Вьюха вызывает `viewModel.login()`, UI переключается в стейт `loading`.
  3. Ответ от `AuthService` (положительный).
  4. Вызов главной очереди -> команда `router.routeToMainTab()`.

### Экран Ленты (Feed Module)
* **Вход:** Данные сессии (открывается по умолчанию при входе в TabBar).
* **Выход:** Событие `didSelectPost(id:)` для передачи фокуса.
* **Состояния (`FeedViewState`):** `loading` (показ ActivityIndicator), `content(items: [FeedUIItem])` (отрисовка таблицы), `empty` (постов нет), `error`.
* **Сценарии:**
  1. Вызов `viewModel.viewDidLoad()` во время готовности UI.
  2. Загрузка массива `Post` через сервис.
  3. Маппинг данных и передача состояния `.content` в Controller.
  4. Пользователь нажимает на определенную ячейку -> вызывается локальный пуш в `UINavigationController` для открытия деталей поста.

### Экран Профиля (Profile Module)
* **Вход:** `userId` (Идентификатор текущего пользователя для запроса в сеть).
* **Выход:** Команда `didTapLogout()`.
* **Состояния (`ProfileViewState`):** `loading` (лоадер без текста), `content(item: ProfileUIItem)` (аватарка-инициалы и никнейм), `error`.
* **Сценарии:**
  1. Переход на вкладку Профиля отрабатывает метод `loadView`.
  2. Идет запрос в `ProfileService`, по ответу генерируются инициалы пользователя.
  3. Нажатие на кнопку "Выйти" -> `Router` анимированно разрушает TabBar и ставит стартовый `AuthViewController` корневым экраном в `UIWindow`.

## Ключевые протоколы и модели
* Доменные: `Post`, `UserProfile`, `AppError`
* Взаимодействие со слоем Data: `AuthServiceProtocol`, `FeedServiceProtocol`, `ProfileServiceProtocol`
* Презентационные (UI-модели): `FeedUIItem`, `ProfileUIItem`
* Контракты: `AuthViewModelProtocol`, `AuthRouterProtocol`, и их аналоги в других модулях.


## Лабораторная работа №3 — Экран авторизации (UIKit)

Реализован полноценный модуль авторизации согласно правилам MVVM:

### Как запустить:
1. Открыть проект в Xcode. 
2. Выбрать симулятор (например, iPhone 15 Pro) и нажать `Cmd+R`.
3. Рекомендуется также запустить на симуляторе `iPhone SE (3rd generation)`, чтобы проверить корректную работу скролла при появлении клавиатуры.

### Данные для входа:
* **Логин:** `admin`
* **Пароль:** `1234`
*(Любые другие данные вызывают ошибку валидации)*

### Что происходит при входе:
1. **Проверка**: При нажатии "Войти" текст кнопки исчезает, появляется системный `UIActivityIndicatorView`, кнопка блокируется на 1 секунду (эмуляция запроса в сеть).
2. **Неверные данные:** Под полем пароля появляется красное Inline-сообщение об ошибке, лоадер исчезает.
3. **Успех:** Отрабатывает `AuthRouter`, который с анимацией `.transitionFlipFromRight` подменяет `rootViewController` окна на заглушку (зеленый экран с текстом об успехе / либо на MainTabBar, если он уже собран).

### Обработка клавиатуры и UI:
Верстка вынесена в `AuthView` и полностью описана с помощью Auto Layout Constraints. Корневым элементом верстки является `UIScrollView`. В `AuthViewController` реализована подписка на нотификации `UIResponder.keyboardWillShowNotification`, которая увеличивает `contentInset` скролла на высоту клавиатуры, не давая ей перекрыть поля ввода и кнопку. Свайп вниз или тап по пустому месту скрывает клавиатуру.
